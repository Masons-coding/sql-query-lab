      How it works
      • SQLite in WebAssembly. sql.js is the real SQLite C library compiled to WASM. It's loaded from a CDN with a Subresource Integrity hash and a strict Content-Security-Policy, so the browser refuses tampered code.
      • Deterministic seed data. The 1,500+ rows are generated by a seeded PRNG, so every visitor and every CI run sees identical data. Flight distances come from the haversine great-circle formula.
      • Relational design. Primary and foreign keys, CHECK and UNIQUE constraints, and indexes on the join columns. The test suite runs PRAGMA foreign_key_check to prove referential integrity.
      • Fair grading. Your query runs on a fresh copy of the database, so earlier UPDATEs or DELETEs can't break an answer. Result sets are compared as multisets, ignoring column aliases and rounding floats to 2 dp. Row order only matters when the question asks for it.
      • Query planning. Explain plan shows SQLite's EXPLAIN QUERY PLAN as a tree, so you can see when an index is used (SEARCH … USING INDEX) vs. a full table SCAN.
